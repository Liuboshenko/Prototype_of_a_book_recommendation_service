## О проекте

В проекте на одном датасете Goodbooks-10k реализованы и сравнены несколько подходов к рекомендациям книг:

1. **Popularity** - неперсонализированный бейзлайн: топ книг по среднему рейтингу с порогом минимального числа оценок.
2. **Content-based** - профиль книги из названия и тегов, векторизация TF-IDF, поиск похожих книг по косинусной близости.
3. **Item-based CF** - коллаборативная фильтрация по схожести книг на разреженной матрице user x book.
4. **SVD** - матричное разложение из библиотеки `surprise`.

Модели, которые выдают top-N рекомендации, сравниваются по метрикам Precision@K, Recall@K и nDCG@K на отложенной выборке. В конце предложен гибридный подход для борьбы с холодным стартом.

**Главный результат.** Лучшее качество рекомендаций показала Item-CF с сортировкой по сумме "схожесть x оценка": nDCG@10 = 0.215, примерно в 300 раз лучше случайных рекомендаций. Второе место у Content-based по профилю пользователя (nDCG@10 = 0.141). Лучший прогноз оценки у SVD (RMSE 0.843), но по ранжированию она почти не отличается от случайных. Точный прогноз оценки не означает хорошие рекомендации.

## Логика решения

### 1. EDA

- **Чистка данных.** Удалены 2 278 повторных оценок (одна книга оценена одним пользователем несколько раз) и 14 аномальных строк в `book_tags` (отрицательный `count` и повторы). Осталось 979 478 оценок, 53 424 пользователя, 10 000 книг.
- **Связи таблиц.** `ratings.book_id` ссылается на `books.id`, а `book_tags.goodreads_book_id` на `books.book_id`. Неправильная связка "молча" совпала бы на 8% строк.
- **Смещение оценок.** 66% оценок - это 4 и 5, средняя 3.86. Поэтому релевантной считается книга с оценкой `>= 4`.
- **Холодный старт.** У 33% пользователей меньше 5 оценок, а 9% активных пользователей (50+ оценок) дают 43% всех оценок.
- **Популярность книг.** В версии датасета с Kaggle у каждой книги не больше 100 оценок, поэтому длинный хвост показан по `books.ratings_count` (число оценок основного издания книги на Goodreads): топ-1% книг собирает 23% оценок, топ-20% - 70%.
- **Теги.** Теги - это пользовательские полки Goodreads. 78% суммарного `count` приходится на служебные теги (`to-read`, `owned`, `kindle` и т.п.), для контентной модели они отфильтрованы.
- **Разреженность.** Матрица пользователь x книга заполнена на 0.18%, у двух случайных книг в среднем 0.54 общих читателя. Разреженная `csr_matrix` занимает 7.7 МБ против 2 ГБ у плотной.

Графики этапа сохранены в `figures/eda_*.png`.

### 2. Popularity и Content-based

- **Разбиение.** Один случайный сплит 80/20 (`random_state=42`) для всех моделей, потому что времени в данных нет. Разбиение сделано до построения моделей, чтобы Popularity, Item-CF и SVD обучались только на train, а все модели сравнивались на одной и той же отложенной выборке.
- **Popularity.** Средний рейтинг книги по train среди книг, у которых не меньше 50 оценок (порог выбран через стандартную ошибку среднего). Функция `get_popular_books(N)`. В топ попадают сборники Calvin and Hobbes и подарочные издания Harry Potter, то есть книги, которые оценивают в основном фанаты.
- **Content-based.** Профиль книги - `original_title` (для 590 книг без него - `title`) и список содержательных тегов без служебных полок. Профили векторизуются `TfidfVectorizer` в разреженную матрицу 10 000 x 40 389, функция `get_similar_books(book_id, N=5)` ищет похожие книги по косинусной близости. Модель хорошо находит книги той же серии, автора и жанра, но склонна рекомендовать "ещё того же".

### 3. Item-based CF

- **Матрица взаимодействий** по train: `csr_matrix` 53 424 x 10 000 с явными оценками, около 9 МБ.
- **Схожесть книг** - косинусная близость по векторам оценок (`cosine_similarity` на разреженной матрице, меньше секунды). Общие читатели есть только у 18.3% пар книг, поэтому и матрица схожестей хранится разреженной: 210 МБ вместо 763 МБ.
- **Прогноз оценки** - взвешенное среднее оценок пользователя по K = 20 самым похожим книгам из его истории. RMSE на test 0.861 против 0.883 у средней оценки пользователя и 0.985 у глобального среднего.
- **Top-N** строится по сумме "схожесть x оценка" по тем же соседям. Сортировка по прогнозу оценки выдаёт случайные книги с прогнозом 5.0, которые держатся на одной слабо похожей книге.
- Разобраны вычислительная сложность (`O(n^2 * m)` в лоб против `sum(d_u^2)` с разреженными матрицами, память `O(n^2)`) и способы оптимизации, а также ограничения CF: холодный старт, разреженность, смещение популярности, сжатие прогнозов к среднему.

### 4. SVD

- **Модель** - `SVD` из `surprise` (Funk SVD): `pred(u, i) = mu + b_u + b_i + q_i * p_u`, 100 скрытых факторов, параметры по умолчанию, `random_state=42`. Обучается на том же train из п. 2.1 примерно за 10 секунд. Параметры занимают 48 МБ против 210 МБ у матрицы схожестей Item-CF, а время обучения растёт линейно с числом оценок.
- **RMSE на test - 0.843**: лучше Item-CF (0.861), средней оценки пользователя (0.883) и глобального среднего (0.985).
- **`get_recommendations(user_id, N=5)`** считает предсказанный рейтинг для всех книг одним умножением матрицы на вектор, исключает книги из train и сортирует по необрезанному прогнозу (обрезка в `predict` до 5.0 создаёт ничьи). Для пользователя без истории используется `mu + b_i`.
- **Персональность.** Top-10 SVD в среднем на 5 книг из 10 совпадает с неперсональным списком по `mu + b_i`. Разброс `b_i` (0.28) больше разброса персональной части `q_i * p_u` (0.12), поэтому наверх выходят книги, которые нравятся всем. Точный прогноз оценки ещё не означает хорошие рекомендации.

### 5. Сравнение моделей

Релевантными считаются книги из test с оценкой `>= 4`. Метрики считаются для 34 288 пользователей, у которых есть история в train и хотя бы одна релевантная книга в test. Книги из train пользователя в рекомендации не попадают. Метрики реализованы вручную и проверены на игрушечном примере.

| Модель | Precision@10 | Recall@10 | nDCG@10 | RMSE |
|---|---|---|---|---|
| Случайные рекомендации (для масштаба) | 0.0004 | 0.0010 | 0.0007 | - |
| Popularity | 0.0006 | 0.0017 | 0.0012 | - |
| Content-based, профиль пользователя | 0.0559 | 0.1691 | 0.1413 | - |
| Item-CF, сортировка по прогнозу оценки | 0.0003 | 0.0008 | 0.0005 | 0.861 |
| **Item-CF, сортировка по сумме "схожесть x оценка"** | **0.0817** | **0.2502** | **0.2154** | 0.861 |
| SVD | 0.0006 | 0.0017 | 0.0011 | **0.843** |

- **Item-CF с сортировкой по сумме "схожесть x оценка"** - лучшая модель для рекомендаций: по nDCG@10 примерно в 300 раз лучше случайных, у 47% пользователей в top-10 есть хотя бы одна понравившаяся книга из test. 61% её попаданий - продолжения серий, которые пользователь уже читал.
- **Content-based** по профилю пользователя (сумма TF-IDF векторов книг, которые он оценил на 4 и 5) на втором месте: nDCG@10 = 0.141, примерно в 200 раз лучше случайных. Сильна она по той же причине: в тегах есть названия серий, авторы и жанры.
- **SVD** лучше всех предсказывает оценку (RMSE), но по ранжированию почти не отличается от случайных: сортировка по предсказанному рейтингу выносит наверх книги, которые нравятся всем, а не те, что пользователь будет читать. Тот же эффект у Item-CF, если сортировать по прогнозу оценки. Дело в цели обучения, а не в самом разложении: то же разложение на матрице "прочитал / не прочитал" (PureSVD) даёт nDCG@10 = 0.039 против 0.0011. Точный прогноз оценки не означает хорошие рекомендации.
- **Popularity** почти бесполезна в этой выборке: у всех книг примерно одинаковое число оценок (потолок 100 на книгу), поэтому книги с высоким средним рейтингом попадают в test почти так же часто, как остальные. Не помогает и популярность по числу оценок: по train и по Goodreads она на уровне случайных или хуже.

График сравнения: `figures/eval_models_comparison.png`.

### 6. Гибридный подход и выводы

**Гибрид против холодного старта.** Модель выбирается по тому, сколько данных есть о пользователе и книге:

| Ситуация | Модель | Почему |
|---|---|---|
| Пользователь без истории | Popularity | Других сигналов нет. Лучше при регистрации попросить отметить несколько любимых книг. Одно место в списке можно отдавать новинкам, чтобы они быстрее набирали оценки |
| Пользователь с историей (от 1 оценки) | Item-CF, "схожесть x оценка" | Лучшая по ранжированию, работает уже при 1-4 оценках (nDCG@10 = 0.19) |
| Новая книга без оценок | Content-based (TF-IDF) | Item-CF и SVD её не видят, а по названию и тегам её можно сравнить с любимыми книгами пользователя. По метрикам этапа 5 это вторая модель после Item-CF. Место в списке новинка получает, только если её схожесть с историей пользователя не меньше 0.2 |
| Ожидаемая оценка книги | SVD | Самый точный прогноз оценки (RMSE 0.843) |

В задании приведён пример "для известных - SVD". Для ранжирования вместо неё взята Item-CF, потому что на наших данных она по nDCG@10 примерно в 200 раз лучше, а SVD используется там, где она сильнее всех, то есть для прогноза оценки. Схема реализована в функции `get_hybrid_recommendations` и проверена на двух пользователях. Например, для читателя "A Series of Unfortunate Events" из пяти "новых" книг без оценок контентная модель выбрала первую книгу этой серии (схожесть 0.62). Если оставить ему только далёкие новинки (лучшая схожесть 0.10), порог их не пропускает и все места получает Item-CF.

**Выводы.**
- Лучшее качество рекомендаций - у Item-CF с сортировкой по сумме "схожесть x оценка", второе - у Content-based, лучший прогноз оценки - у SVD.
- Главный урок: точный прогноз оценки не означает хорошие рекомендации. Модель и критерий ранжирования нужно выбирать под задачу.
- Сильные и слабые стороны всех моделей и 14 путей улучшения описаны в ноутбуке (п. 6.2). Среди них неявный фидбек (ALS, BPR), SVD++, двухэтапная схема с learning-to-rank, эмбеддинги текста (Word2Vec, BERT), использование `to_read.csv`, признаки пользователей и временное разбиение.
